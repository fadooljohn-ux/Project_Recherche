# Candidate deep-review policy

The owner directed on 9 September 2026 that compelling candidates receive a
deep review every time. A qualifying original threshold crossing whose input
and numerical checks survive is the default trigger for this follow-up.
An identified import or execution artifact is repaired and documented first.

Use a bounded, recorded scope appropriate to the target: correlated and
frequency-dependent noise alternatives; noise-only simulations and signal
injections repeating the same model/frequency selection; observing-day
influence and time/receiver-band consistency; and independent-source or
alternate-reduction comparisons where data permit. Reuse completed diagnostics
when they answer the same question. Declare model choices, grids, seeds and
simulation counts before the new review calculations. Report unavailable or
unidentifiable checks explicitly.

Preserve the original search threshold and result. A follow-up simulation tail
is conditional on its stated noise family, not a planetary probability or a
replacement campaign false-alarm rate. Deep review can leave a candidate
inconclusive; it need not produce a detection or rejection.

Checkpoint the work, repair actual errors and continue only missing steps.
Avoid general redesigns and repeated qualification. Use the requested 30-minute
heartbeat for healthy long jobs. Close out in a scientific report and update
the canonical master workbook, retaining all prior records and operator notes.
Share new results or change repository visibility only within the owner's authorization.

At each review closeout, record the three measures in
[Candidate evidence grading](CANDIDATE_GRADING.md): search-adjusted significance,
signal robustness and independent confirmation. Supply explanations and evidence
bindings. Keep conditional simulation tails separate from global FAP/sigma.
Use the existing master updater to enter the assessment; missing grades remain
review pending. Reuse completed evidence when it answers the grading question.
